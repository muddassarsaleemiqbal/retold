# Authoritative script editing

The video workspace now reads and edits the actual saved master script. This completes the
script portion of G5; scene, character, localized audio and full media review remain separate
work in the GUI plan. The fictional G0 lab remains clearly separate.

## Content, history and approval

`retold-engine::editing` owns bounded, immutable baseline/revision documents under
`.retold/edits`, plus an atomically published current pointer. Reads create no editing files
and verify schemas, content hashes and revision bindings. The original model cache remains
immutable. The generated `work/02-script/script.json` mirror changes when the pipeline consumes
the approved revision, rather than being mistaken for the authoritative editing pointer.

Every save, approval, undo and redo requires the exact version shown by the reader and takes
the existing exclusive run lock. The version includes pointer bytes, generated bytes, the
verified script record and source context. Another client or generator changing those inputs
rejects the write and preserves the caller's text. Drafts may contain incomplete text;
approval checks deterministic guide quality and pins the current content hash. Content changes,
undo and redo clear approval. History pages contain at most 64 immutable revisions.

Saving narration invalidates both the storyboard and speech branches, including descendant
character/media, caption, timeline and delivery records. Research and writer caches remain
reusable. Invalidation is saved before the new pointer: a failure between publications leaves
the previous current text and conservative invalidation, never new text with old ready deliveries.
The pointer digest independently binds reviewed runs, including approval-only changes.

The pipeline checks the manual revision before model work and consumes approved content after
reusing its original generated baseline. Changed sources, frozen guide/channel, research/plan,
inputs or writing revisions block old manual text before model dispatch. Undo can return to the
baseline before explicit regeneration. A current session reports missing manual approval as a
review blocker; a stale reviewed session reports changed authority.

## Shared clients

`retold-app::editing` supplies typed document, mutation, impact and history operations using
catalog identity resolution and the existing account maintenance barrier. GUI and CLI use this
same boundary. Commands are:

```sh
retold video script show VIDEO
retold video script edit VIDEO --section hook --text 'Revised narration' --expected-version HASH
retold video script approve VIDEO --expected-version HASH
retold video script undo VIDEO --expected-version HASH
retold video script redo VIDEO --expected-version HASH
retold video script history VIDEO
```

History accepts its returned JSON cursor through `--cursor`. These operations grant no provider,
queue, spending or export authority. The older generic review edit-history handlers are not used
as semantic script editing and remain unsuitable for pretending that shot/cast content changed.

The native Script view provides section editing, saved-version comparison, retained text on
conflict, explicit latest-version/local-text choices, quality messages, approval, undo/redo and
revision browsing. Switching views retains the editor; unsaved text participates in the native
quit guard. Saving disables input until the captured request finishes. Checking a newer saved
version keeps local text and requires an explicit conflict choice before overwriting it.

## Evidence

Engine regression checks cover cache reuse by an actual pipeline, immutable/bounded history,
tampered revisions, stale editor and history versions, source changes before provider calls,
generation locks, undo/redo, full downstream invalidation and Unicode. Session checks cover
review classification and the independent manual-pointer authority check with an older state
index. CLI integration checks exercise real Save/Approve/Undo/Redo/History commands and a
conflicting second writer without admitting any queue job.

The actual native Metal journey saves and approves content, keeps Hindi/Urdu/English text after
a concurrent write, rejects a stale save, then applies the retained text only after the user
chooses it. Native captures include normal/approved wide dark, compact light and conflict states
under `/tmp/retold-gpui-g0-evidence`. This is not a claim of human IME, VoiceOver or all-platform
qualification. Unsaved crash recovery and localized/scene edits remain subsequent acceptance work.
